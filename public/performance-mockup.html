What is this page?

A private internal dashboard for YouTube / Demand Gen creative performance. Slack stays for spend alerts. This site is for browsing a leaderboard, pivot summaries, and one-creative detail — with login so the link is not publicly usable.

The three views

  1. Leaderboard — ranked list of creatives (who’s winning).
  2. Pivot — rolled-up totals by client / campaign (like a pivot table).
  3. Creative detail — full 30d stats + chart for one video (like your Slack thread).
Click the tabs below to see a sample UI. Data is fake/demo for layout only. Ops docs: 5. Credentials (how to get env), 6. Deploy, 7. Countermeasures (security + production pitfalls).

How we wire this into the n8n workflow

Keep the existing Slack alert flow. Add a performance store write so the private web app can read leaderboard / pivot / detail data.

End-to-end flow

Google Ads API ↓ n8n (existing creative spend alerts) ↓ Format Merge 30-Day Metrics + Quartile ← already has KPIs ↓ NEW: Upsert Performance Store ← Sheet tab or BigQuery ↓ (rest unchanged) Chart → IF → Launch Date → Slack → Write Alert Log ↓ yt.naturalabs.io/performance (Next.js) ↓ Google OAuth (@naturalabs.io only) → Leaderboard / Pivot / Detail

Where to add the new node (per branch: 50K / 20K / 10K)

… → Format Merge 30-Day Metrics + Quartile ↓ Upsert Performance Store ← NEW (Google Sheets Append/Update OR BigQuery) ↓ Create Short Chart URL → IF → Get Launch Date → Format Launch Date ↓ Slack message → Send a message → Write Alert Log
Best practice: write performance rows from Format Merge (all creatives that reach metrics), not only after Slack — so the leaderboard can include more than just alerted creatives. For a full client leaderboard, add a separate nightly “refresh all creatives” workflow later.

No webhook needed

n8n does not call the web app. Sheets/BigQuery do not notify the app. n8n writes rows; the Next.js app reads on page load.

Two build options

OptionStoren8n nodeApp reads with
MVP (faster) Private Google Sheet tab performance_leaderboard Google Sheets — Append or Update row Service account → Sheets API
Scale (better) BigQuery table creative_performance_30d BigQuery — Insert / Upsert Service account → BigQuery
Sheet stays not shared publicly. Only the service account + n8n credential can access it. Humans use yt.naturalabs.io/performance only.

App side

  1. Deploy Next.js to GCP Cloud Run (recommended) → DNS yt.naturalabs.io
  2. Route /performance → Leaderboard (default)
  3. Server reads Sheet with service account (never in browser)
  4. NextAuth Google login → reject any email not ending in @naturalabs.io
  5. Optional: Cloudflare Access / IAP for a second gate

Step-by-step (what we did)

  2. Create Artifact Registry Docker repo (e.g. yt-performance)
  3. Push app to GitHub automatesolutions/yt-performance (no secrets in repo — Push Protection blocks real OAuth secrets)
  4. Connect GitHub → Cloud Build trigger; grant Cloud Build SA Developer Connect Read Token Accessor (+ Secret Manager accessor if needed)
  5. On push: Cloud Build runs Docker build + deploys service yt-performance
  6. Cloud Run → Edit & deploy new revision → Variables: paste all keys from tab 5 (auth + service account + spreadsheet id + tab). Verify on the revision with 100% traffic
  7. Google OAuth: add Cloud Run URL as origin + /api/auth/callback/google redirect

Ingress: allow unauthenticated (app does Google login). Port: 8080. Prefer Secret Manager for client secret / NextAuth secret / SA private key. After each code fix: commit → push → wait for Cloud Build (no local npm run build required for Cloud Run).

Countermeasures — getting data & deploying safely

Lessons from production setup. Use this when login shows yellow text, Leaderboard says Demo data, Cloud Build fails, or secrets leak.

Never commit real .env values, paste secrets into HTML/README, or put OAuth / SA keys in chat, screenshots, or .env.example. If exposed: ROTATE OAuth client secret, regenerate NEXTAUTH_SECRET, and create a new SA key (delete the old JSON key).

3) Safe checklist — before / after every deploy

  1. Secrets: only in local .env (gitignored) + Cloud Run / Secret Manager — never git, HTML, or chat
  2. Auth trio present on live revision: Client ID (full), Client secret, NextAuth secret
  3. NEXTAUTH_URL matches the URL in the browser bar
  4. OAuth origin + callback match that same host
  5. SA private key valid PEM; Sheet shared Viewer; tab = performance_leaderboard
  6. Allowlist = company domains only (no broad Gmail in prod)
  7. Cloud Build SUCCESS after push; test the revision that has traffic
  8. Smoke test: /login shows Sign in with Google; /performance shows Live Sheet
  9. If anything secret leaked → ROTATE before continuing

4) Quick decision tree

Login yellow “Auth is not configured” → Check live revision env (3 auth vars, full Client ID) → If present: ensure latest image (force-dynamic + getEnv) is deployed → Hard refresh /login Leaderboard “Demo data” → Cloud Run Logs → search [sheets] or ERR_OSSL → Fix PRIVATE_KEY PEM format + Sheet share + spreadsheet ID/tab → Redeploy revision → expect “Live Sheet” OAuth error / redirect_uri_mismatch → Align NEXTAUTH_URL + Google Console origin/callback AccessDenied → ALLOWED_EMAIL_DOMAINS + OAuth Test users Build fails fetchReadToken → IAM on cloudbuild service account Push blocked (secret scanning) → Remove secrets from files; rotate; push placeholders only
